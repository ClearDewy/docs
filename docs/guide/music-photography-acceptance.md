# 音乐与摄影整合与修复记录

这份记录供维护者和验收者复查实现。自动检查只能说明路由、事实计算、状态边界和生产构建符合已写下的规则，不能证明零基础学习者已经看懂。课程是否有效仍需观察学习者能否独立开始、预测变化、指出变化位置、解释原因，并在另一个例子中复用。

## 2026-09-09 可理解性复审纠正

首版虽有连续目录、可点击控件和正确的基础计算，但复审发现两条核心路径仍然以短文字定义为主。音乐把术语放在听觉经验之前，吉他页还并列了理论和弦与另一套指板状态；摄影主图被三栏布局压到约 280px，曝光、暗部、直方图和完整参数同时争夺注意力。此前的“顺序学习通过”结论因此撤回。

本轮只集中重做样板入口：音乐先用可见音阶建立“一格就是半音”，再用固定 C 指型逐弦解释“五根弦为何只有三个音”；摄影先用标注区域示范怎样写观察，再在同一视区比较曝光与暗部。重做页隐藏右侧目录和按字数计算的阅读时长，正文展示实际预计练习时间。完整探索工具仍保留为后续入口。

## 当前范围

- 音乐形成“声音与音高 → 吉他和弦 → 大调 → 节奏 → 第一首歌 → 选调、录音与反馈”的连续学习路径。
- 摄影形成“观看 → 拍摄 → 影调 → 色彩 → 两种方向 → 参考拆解 → 实拍复盘 → 素材收集”的连续学习路径。
- 两个专栏都提供总览、知识地图、可操作练习、证据记录方式和下一步。
- 首版不把合成音视为本人演奏，不使用自动分数判断摄影审美，也不声称尚未留下录音或照片的个人实践已经完成。

## 开源组件选择

以下版本来自 2026-09-09 的 npm 安装结果和包元数据。

| 组件 | 当前版本 | 许可证 | 官方来源 | 选择理由与边界 |
| --- | --- | --- | --- | --- |
| Tone.js | 15.1.22 | MIT | [Tone.js 仓库](https://github.com/Tonejs/Tone.js) / [官方文档](https://tonejs.github.io/docs/15.1.22/) | 负责浏览器音频调度与合成；只在用户操作后启动 AudioContext，不在 SSR 阶段访问浏览器音频对象。 |
| Tonal | 6.4.3 | MIT | [Tonal 仓库](https://github.com/tonaljs/tonal) / [官方文档](https://tonaljs.github.io/tonal/docs/) | 提供音名、和弦和移调的纯数据计算，避免页面、组件和测试各自维护音乐事实。 |
| img-comparison-slider | 8.0.7 | MIT | [官方仓库](https://github.com/sneas/img-comparison-slider) / [官方站点](https://img-comparison-slider.sneas.io/) | 使用成熟的键盘可操作图片对比控件，避免重复实现拖拽、焦点和 Web Component 行为。 |
| @img-comparison-slider/vue | 8.0.0 | MIT | [官方 Vue 包](https://github.com/sneas/img-comparison-slider/tree/master/packages/vue) | 在 Vue 3 中封装同一对比控件；组件在 `onMounted` 后动态导入，SSR 使用静态并排图片回退。 |

所有面向 Markdown 的组件继续在主题中通过 `defineAsyncComponent` 注册。音乐音频引擎在点击试听后加载；摄影的图片对比包只在客户端挂载。页面正文和静态回退保留同一结论，交互不是唯一信息来源。

`npm audit --omit=dev` 仍报告 7 个来自既有 VitePress 1.6.4、Vite 与 Teek 依赖链的告警（6 个 moderate、1 个 high），当前解析结果为没有可用修复。报告没有列出本次四个新增直接依赖的漏洞；后续升级站点框架时需要重新审计，不能用自动 `npm audit fix` 越过现有主题补丁和构建兼容边界。

## 仍需真实学习者验收

本轮已经做工程检查和桌面、390px 移动视口的操作走查；发现的窄正文、移动浮动按钮遮挡、旧锚点和控件位置问题均已修正。它仍不是新手学习效果证明。

真实试用至少完成四项：在不知道答案时独立找到第一个操作；先预测下一步会变什么；指出声音或照片中变化的具体位置；换一个起点、音组或画面区域后重新解释。卡住的位置、原话和日期应写入下一轮复审，不能用按钮响应或测试通过替代。
